# 텔레그램 알림봇 골격

## 이 도구가 하는 일 (비개발자용)
서버·수집기·자동화가 내는 경보와 리포트를 텔레그램으로 보내는 알림봇 골격입니다. 어떤 자동화 프로젝트에든 붙는 알림 부품으로, "보내는 코드"가 아니라 실패해도 유실되지 않는 전달을 목표로 만들었습니다.

## 어떤 문제를 풀었나
자동화가 늘수록 "그 경보가 정말 도착했는가"가 중요해집니다. 알림이 도착하지 않으면 감시는 무의미한데, 알림이 사라지는 지점은 늘 가장자리입니다 — 네트워크 순단, 텔레그램의 발송 속도 제한(429), 4096자 메시지 한도. 이 가장자리에서 조용히 유실되는 알림이 사고를 키웁니다.

## 결과
- **경보를 놓치지 않는 채널** — 서버·수집기·정산 작업의 이상을 텔레그램으로 바로 받습니다. 텔레그램이 잠시 안 되면 보류했다가 복구 후 순서대로 다시 보냅니다.
- **긴 리포트도 통째로** — 4,096자 한도를 넘는 메시지는 자동 분할돼 원문 그대로 도착하고, /status 같은 명령으로 현재 상태를 물어볼 수 있습니다.

## 쓰는 법
```
python tg_notify.py
```
데모 데이터가 동봉되어 있어 실행 즉시 결과와 검증 리포트가 생성됩니다. 실제 적용은 설정값(규칙·경로·계정)만 1회 맞춥니다.

## 검증 (6/6 PASS)
- ① 발송 전수 대조(5건, 순서 포함)
- ② 장문 분할(4096 한도, 2조각) → 서버측 재조립 = 원문
- ③ 429 레이트리밋 → retry_after 존중 후 성공(유실 0)
- ④ 영구 실패 → 보류 큐 → 복구 후 재송(보류분 우선·큐 소진)

전체 항목은 같은 폴더의 검증 리포트(md)에 있습니다.

## 정직 고지
데모 화면·데이터는 합성 데이터입니다. 이 문서는 도구의 동작 범위를 설명하며, 회계·세무·법률 자문이 아닙니다.
