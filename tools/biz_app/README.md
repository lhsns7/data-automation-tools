# 내부 업무 웹앱 골격

## 이 도구가 하는 일 (비개발자용)
엑셀·메모로 굴리던 고객·주문 관리를 웹 시스템으로 옮길 때 쓰는 뼈대입니다. 화면을 예쁘게 만드는 것보다 내부 시스템에서 실제로 사고가 나는 자리 — 권한이 없는 사람이 지우는 것, 두 사람이 같은 데이터를 동시에 고쳐 한쪽이 사라지는 것, 누가 언제 바꿨는지 모르는 것, 엑셀에서 불량 데이터가 섞여 들어오는 것 — 을 구조로 막는 데 집중했습니다.

## 어떤 문제를 풀었나
"엑셀로 관리하던 걸 시스템으로 옮겨 달라"는 요청에서 진짜 문제는 화면이 아닙니다. 엑셀 시절엔 파일 하나를 여러 사람이 돌려 쓰다 누군가의 수정이 사라지고, 누가 지웠는지 아무도 모르고, 다른 파일에서 붙여 넣은 불량 데이터가 조용히 섞였습니다. 웹으로 옮겨도 권한·동시 편집·이력·입력 검증이 없으면 같은 사고가 더 빠르게 납니다.

## 결과
- **"누가 지웠지"가 없어짐** — 생성·수정·삭제·가져오기 전부 누가·언제·전→후 값으로 감사 로그에 남고, 지울 권한은 관리자에게만 있습니다. URL을 직접 쳐도 서버가 막습니다.
- **수정이 사라지는 사고 차단** — 두 사람이 같은 데이터를 동시에 고쳐도 나중 저장은 충돌로 잡히고 최신 값을 보여줍니다. 엑셀 시절의 "내가 고친 게 없어졌어요"가 구조적으로 없습니다.

## 쓰는 법
```
python biz_app.py --serve  (검증: python biz_app.py)
```
데모 데이터가 동봉되어 있어 실행 즉시 결과와 검증 리포트가 생성됩니다. 실제 적용은 설정값(규칙·경로·계정)만 1회 맞춥니다.

## 검증 (8/8 PASS)
- ① 인증: 미로그인 → 로그인 이동 · 오답 거부(세션 0) · 비밀번호 평문 저장 0
- ② 권한 우회 차단: viewer 생성 → 403·저장 0 · staff 삭제 → 403·잔존 · ★참조 중 고객 삭제 → 거
- ③ CSRF: 토큰 없음/불일치 POST → 403 · 저장 0
- ④ ★동시 편집: 두 세션 같은 레코드 → 첫 저장 성공(version+1) · 둘째 409 충돌 · 첫 값 보존

전체 항목은 같은 폴더의 검증 리포트(md)에 있습니다.

## 정직 고지
데모 화면·데이터는 합성 데이터입니다. 이 문서는 도구의 동작 범위를 설명하며, 회계·세무·법률 자문이 아닙니다.
