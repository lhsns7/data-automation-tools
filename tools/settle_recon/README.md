# 카드 매출 마감 대사

## 이 도구가 하는 일 (비개발자용)
매장·온라인 사업자의 일 마감 질문 — "오늘 통장에 들어온 카드사 입금이 왜 이 금액인가?" — 에 자동으로 답하는 대사 도구입니다. 카드 매출은 승인일과 입금일이 다르고(카드사별 D+N 영업일), 수수료가 차감되고, 취소가 다른 날 끼어들어 통장과 POS가 눈으로는 맞지 않습니다. 그 사이를 규칙으로 잇습니다.

## 어떤 문제를 풀었나
카드 매출의 입금은 며칠 뒤에, 수수료를 뗀 채로, 카드사마다 다른 주기로 들어옵니다. 그래서 "매출은 맞는데 통장이 안 맞는" 상태가 기본값이고, 사장님은 매일 저녁 그 차이를 눈으로 맞추거나 — 대부분은 — 포기합니다. 문제는 진짜 사고(입금 누락·수수료 오적용)가 바로 그 일상적 소음에 묻힌다는 겁니다. 안 맞는 게 기본값인 장부에서는 진짜 안 맞는 것도 안 보입니다.

## 결과
- **"입금이 왜 이 금액인지" 자동 답변** — 카드사별 수수료와 입금 주기(영업일)를 반영해 예상 입금을 만들고 실제 입금과 대조합니다 — 통장과 POS를 눈으로 맞추는 일이 없어집니다.
- **미입금을 전화 한 통 거리로** — 안 들어온 입금은 카드사·일자·금액까지, 금액이 다른 입금은 차액까지 특정됩니다. 정상 건은 전부 소거돼 사고만 남습니다.

## 쓰는 법
```
python settle_recon.py
```
데모 데이터가 동봉되어 있어 실행 즉시 결과와 검증 리포트가 생성됩니다. 실제 적용은 설정값(규칙·경로·계정)만 1회 맞춥니다.

## 검증 (6/6 PASS)
- ① ★영업일 수기 3케이스(금+2=공휴일 넘어 수요일 등)
- ② 정상 건 전부 일치(심은 2건 외 차이 0 = 오탐 0)
- ③ ★심은 미입금 정확 검출(카드사·일자·금액)
- ④ 심은 수수료 오적용 → 차액까지 정확

전체 항목은 같은 폴더의 검증 리포트(md)에 있습니다.

## 정직 고지
데모 화면·데이터는 합성 데이터입니다. 이 문서는 도구의 동작 범위를 설명하며, 회계·세무·법률 자문이 아닙니다.
