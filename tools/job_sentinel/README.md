# 자동화 작업 감시

## 이 도구가 하는 일 (비개발자용)
크론·스케줄 작업들이 "아직 잘 돌고 있는지"를 감시하는 워치독입니다. 자동화 운영의 진짜 위험은 실패가 아니라 침묵 실패 — 작업이 죽어도 아무도 모르는 상태 — 라는 문제의식으로, 자체 수집기·서버 크론을 몇 달 운영하며 겪은 것을 일반화해 만들었습니다.

## 어떤 문제를 풀었나
자동화가 5개, 10개로 늘면 어느 날 하나가 조용히 죽어 있습니다. 그리고 그걸 며칠 뒤 "데이터가 왜 비었지?"로 발견하게 됩니다. 실패 알림은 실패해야 울리는데, 죽은 작업은 실패조차 보고하지 않기 때문입니다 — 이것이 자동화 운영의 가장 흔하고 가장 늦게 발견되는 사고, 침묵 실패입니다.

## 결과
- **조용히 멈춘 자동화를 그날 발견** — 크론·배치가 정해진 시간 안에 신호를 안 보내면 그 작업만 지연으로 표시하고 알립니다 — 며칠 뒤 "왜 리포트가 안 왔지"가 없습니다.
- **알림이 무시되지 않게** — 같은 상태를 반복해서 울리지 않고 문제 발생 1번, 회복 1번만 알립니다. 실패 사유는 상태판에 그대로 남습니다.

## 쓰는 법
```
python job_sentinel.py --beat 작업명 [--fail --note 사유]
```
데모 데이터가 동봉되어 있어 실행 즉시 결과와 검증 리포트가 생성됩니다. 실제 적용은 설정값(규칙·경로·계정)만 1회 맞춥니다.

## 검증 (6/6 PASS)
- ① 정상 3작업 = 전부 OK (최초 OK는 조용)
- ② ★침묵 실패(80분 무소식 > 60+10) → 그 작업만 LATE
- ③ 실패 보고 → FAIL + 사유 보존("SMTP 연결 거부")
- ④ ★경보 피로 방지(같은 상태 재검사 = 알림 0 · 회복 = 회복 알림 1)

전체 항목은 같은 폴더의 검증 리포트(md)에 있습니다.

## 정직 고지
데모 화면·데이터는 합성 데이터입니다. 이 문서는 도구의 동작 범위를 설명하며, 회계·세무·법률 자문이 아닙니다.
